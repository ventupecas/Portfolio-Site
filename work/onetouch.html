OneTouch

An IT ticket workspace: ask about ServiceNow tickets in plain English, get the answer as a table or a chart, and see which work needs attention first.

  • Claude API
  • PostgreSQL
  • Cube

The problem

An IT team’s tickets (incidents, changes, requests and tasks) come out of ServiceNow as a set of exports. Questions like “which teams have the most open incidents?” or “what emergency changes happened this week?” should have an answer anyone on the team can get in seconds, without building a spreadsheet first.

How it works

  1. You ask a question in plain English, in the chat or in the bar at the top.
  2. Claude turns it into a structured query. OneTouch checks what comes back, and Cube, a data layer over PostgreSQL, runs it.
  3. Every query only covers the teams that person is allowed to see.
  4. The answer comes back as a table you can download in eight formats, or as a chart. There are also ten ITIL dashboards in Metabase, and dashboards people build themselves.
  5. An Architecture page draws the whole system in 2D and 3D, with live health checks and a risk monitor that turns a block red when something is about to go wrong.

Decisions I made

  • The AI never touches the database. Claude describes the query, OneTouch checks it, and Cube runs it.
  • Plan for the internet failing in the middle of a live presentation. Answers are saved, and an offline switch lets the assistant answer from them while everything else keeps running on one computer.
  • A daily AI budget and a usage report, so the cost is visible before it becomes a problem.
  • Accounts with passwords, visibility by team, and a lockout after repeated wrong passwords.

The hard part: keeping the documentation true

The README explains every feature, how to run it and how to rebuild it from scratch, with every file printed in full. A check fails as soon as the README no longer matches the code, so it can’t go stale without anyone noticing.

In numbers

  • 8download formats for every answer
  • 10ITIL dashboards
  • 2D + 3Dmaps of its own architecture
  • 6risks watched live, from disk space to password guessing

OneTouch was built for a real IT team, so the portfolio demo uses generated data and prepared answers in place of Claude. No real tickets, names or client details appear in it.
